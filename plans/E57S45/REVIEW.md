# E57S45 v4 路网合并后复查

本页保留部署前的复查结论。用户随后授权殖民；2026-11-08 的部署与殖民启动状态见 [COLONIZATION.md](COLONIZATION.md)。

结论：修正 v3 主路线锁定过多的问题后，道路从 166 降至 135 格。源2平直通道、14 条主路线最短步数、各阶段服务距离及最差补给模型表现均保留；前三项物流修正继续生效。本地复查未发现阻塞项。未下旗、未部署，未进行线上实测。

## 1. 矿箱与 Link 生命周期

- 蓝图保持西矿、北矿 Container，矿工在相应 `preserveMiningBuffers` 策略启用且坐标明确列入规划时不会拆箱。
- 未列入规划或未启用策略的房间继续沿用原行为。
- Link 满时，矿工可将能量转入保留矿箱，避免缓冲箱只有坐标而没有实际作用。
- 回归验证：保留规划箱、清理非规划箱、保留非 opt-in 行为、Link 满时能量转入矿箱。

## 2. Link 的实际发送优先级

- Storage 旁的核心 Link 先接矿区输出，不受控制器、孵化区请求插入顺序影响。
- 每个发送端每 tick 最多成功发送一次，每个接收端最多接收一次成功发送；容量来自 tick 起始状态，避免延迟意图重复占用同一容量。
- 忽略冷却中的发送端；失败返回不消耗接收额度。
- 核心满时可先转发已有能量；额外矿区输出可以服务其他节点，避免严格独占造成永久饥饿。
- 未启用策略的殖民地维持原调度。

## 3. Queen 补给缓冲

- 充足 Container 优先于 800 容量 Link；部分 Carry 的补给按剩余容量判断。
- 缓冲不足时使用可用能量较多的来源，不等待箱满；没有缓冲能量时可回退到 Link。
- 不打断有效的取能或运送任务。
- 相同离线满缓冲模型中，RCL8 最差结果由 268 降至 195 tick；有 Link 与无 Link 时均能选择充足 Container。该数字是模型比较，不是实际服务器 tick 承诺。

## 4. 道路复用与空间布局

- v3 的裁剪锁定全部主路具体格子，因此“单格不可继续删除”未证明整体网络足够紧凑。v4 只锁定源2到 Storage、Spawn 的具体路线，其他主路可以改用等长共享通道。
- 比较四种确定性裁剪顺序，均从 166 降至 **135 格**，减少 31 格（18.7%），比最初 129 格净增 6 格。没有新增 v3 以外的路格。
- 每次尝试删除道路都重新计算 14 条主路线、RCL2–8 全部建筑服务距离和各级最差补给模型；任一退化即拒绝。最终按新路网重算路线，独立地形 BFS 验证全部 14 条仍是最短路径，不再把具体旧路径作为不可删除条件。
- 源2到 Storage 仍为 20 步、1 次转弯；到 Spawn 仍为 22 步、2 次转弯。14 条路线合计仍为 258 步。
- 总转弯由 v3 的 52 变为 58；部分次要路线增加转弯换取道路共享，源2到控制器的转弯从 7 减为 4。转弯数不等同于移动耗时。
- 所有 RCL2–8 的核心服务距离和最差补给模型均不退化，RCL8 仍为 195 tick。重新以四种顺序裁剪当前结果，没有可再删除的单格。
- 全部建筑坐标和建设顺序、Link 优先级、38 格外围防线与三个门位保持不变。
- RCL1–8 建筑上限、地形冲突、可达性、实验室范围及防线检查通过。

## 5. 生成与运行时蓝图一致性

- 生成器从固定建筑候选重建 v3 作为可复现比较基线，再做 v4 路网合并，不依赖现有输出文件反向作为输入。
- `routing-review.json` 的 `networkCompaction` 记录 v3→v4 的候选、31 格删除坐标、各路线前后指标和逐级补给比较；根级道路增删仍以最初 129 格方案为基线。`roadPruning` 保留 v3 的三格历史裁剪记录。
- 运行时模板版本更新为 `E57S45-terrain-v4`，包含新分级道路。已拥有房间的旧模板即使 RCL 不变，也可在未来获准部署后刷新本地规划 Memory；本次没有执行安装或改动线上 Memory。

## 接入边界

E57S45 的策略由其本地自定义模板启用；安装要求已拥有该房间、shard 匹配。重复安装与 RCL 升级均有测试。未拥有或 shard 不匹配时不安装；函数没有创建殖民旗或执行占领的路径。E58S42 及其他殖民地的默认物流策略不因这些 opt-in 分支改变。

- `npm test`：19 个测试文件、108 项测试通过，包含本地打包与 bundle 检查。
- `python3 scripts/test_e57s45_routes.py`：9 项测试通过，新增共享道路替换原主路、逐阶段服务及补给不退化验证，并将稳定性检查改为 v4 合并算法。
- `python3 scripts/plan-e57s45.py --check`：蓝图、运行时代码、路线审查和总图一致。
- `npm run check`：格式、lint、类型检查通过。
- 地图数据及交互逻辑在 320/736px DOM 宽度检查通过，SVG 总图已渲染查看；未将此表述为完整浏览器测试。

共享通道可能集中流量；尚未覆盖真实堵车、战争和动态缺能的线上表现，也不将有限候选与单格裁剪搜索描述为全局数学最优。
